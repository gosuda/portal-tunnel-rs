# utoipa Coverage Policy (Phase 7 U8.8)

The portal-tunnel-rs HTTP surface is documented by `utoipa` and served at
`/__docs/openapi.json` via `utoipa-axum`. Coverage is enforced at PR time so
endpoints cannot ship without an OpenAPI registration.

## The rule

**Library crates** (`portal-relay`, `portal-sdk`) MUST register every route via
`utoipa_axum::OpenApiRouter::route` and `OpenApiRouter::nest`. Calling
`axum::Router::route` or `axum::Router::nest` from a library crate is a CI
failure.

**Binary crates** (`portal-relay-bin`, `portal-cli`, `portal-demo`) compose the
finalised `axum::Router` at the mount site, where the bare `axum::Router::route`
/ `Router::nest` calls are legitimate (the routes have already been registered
upstream by the library crate). Binary crates may locally bypass the lint at
the single mount-site call:

```rust
let app = library_built_router
    .nest("/v1", inner)  // (1)
;
```

becomes:

```rust
#[expect(
    clippy::disallowed_methods,
    reason = "binary crate composes utoipa-registered routers at the mount site (Phase 7 U8.8 / docs/utoipa-coverage-policy.md)"
)]
let app = library_built_router
    .nest("/v1", inner);
```

## Enforcement

Two independent CI signals with overlapping coverage:

1. **Clippy `disallowed-methods`** (`clippy.toml`) — **primary gate**. Operates
   on resolved Rust paths after name resolution (resolves to `DefId`, not the
   surface path). Catches both the associated-fn shape
   `Router::route(&mut r, ...)` and the method-call shape `r.route(...)`,
   regardless of import alias (`use axum::Router as R;` does not defeat it).
   Misses code that's never reached by the lint pass — typically:
   - Code generated by macros where the lint scan does not see the expanded form.
   - Code paths gated behind `cfg` flags that are disabled in the CI build.

2. **`ast-grep` belt-and-suspenders** (`.github/workflows/ci.yml`,
   `utoipa-coverage-gate` job) — **source-shape gate**. Operates on syntactic
   shape, scoped to library crates. Catches the canonical chained-builder forms:
   - `Router::new().route(...)` / `Router::new().nest(...)`
   - `axum::Router::new().route(...)` / `axum::Router::new().nest(...)`

   Bound-to-var rebinds (`let r = Router::new(); r.route(...)`) are caught by
   clippy via type resolution, not by ast-grep — ast-grep cannot follow type
   information across statements. Macro-expanded calls that surface as the
   chained-builder shape in source ARE caught by ast-grep even when clippy
   misses them post-expansion.

## Escape procedure

A library crate that needs to bypass — for example, mounting a router that
does not have a corresponding utoipa registration (third-party middleware, a
testing endpoint that should not appear in user-facing docs) — adds the
`#[expect(clippy::disallowed_methods, reason = "<specific reason>")]`
annotation at the call site WITH a reason that names:

- The specific endpoint being mounted.
- Why utoipa registration is not appropriate.
- Whether this is a v0.1 carve-out or permanent.

Reviewers verify the reason during code review. The `reason = "..."` field
on `#[expect]` is technically optional in stable Rust 2024 — there is no
workspace lint (such as `clippy::allow_attributes_without_reason`) currently
configured to make it a hard CI gate. Enforcement is reviewer discipline
plus project convention: every existing `#[expect(clippy::disallowed_methods,
...)]` site in the workspace carries a specific reason naming the R9 / R2 /
utoipa carve-out it claims (see [`architecture.md`](architecture.md) §R9 for
the approved justification phrasings). A reasonless `#[expect]` is rejected
at code review on that basis.

`ApiDoc::openapi()`; CI asserts the committed copy matches the generated
output) is a v0.2 backlog item per the roadmap plan §v0.2 Backlog. The v0.1

the clippy + ast-grep enforcement above.
