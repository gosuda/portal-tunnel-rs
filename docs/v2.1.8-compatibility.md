# v2.1.8 Compatibility Status

Last updated: 2026-05-02

This document tracks compatibility between the Rust relay and the official
`gosuda/portal-tunnel` `v2.1.8` client release.

## Release Baseline

- Upstream release: <https://github.com/gosuda/portal-tunnel/releases/tag/v2.1.8>
- Tag commit: `3bb510c356e74268f1b3aa89b742c6661ff2ac4f`
- Official Linux arm64 binary verified by release checksum before smoke testing.

## Not Yet Verified

| Surface | Status |
| --- | --- |
| Public discovery expansion/polling behavior against v2.1.8 clients | Implemented locally, including public registry bootstrap merge; not yet smoke-tested against official v2.1.8 relay meshes |
| Multi-hop/WireGuard overlay runtime | Experimental runtime is wired with `tokio-wireguard`, but not yet end-to-end verified against Go v2.1.8 relay meshes |
| Public ingress next-hop forwarding | Wired for SNI ingress when HopMux exists; not end-to-end verified over the overlay data path |

## Reproduce

```bash
./scripts/v218-release-http-smoke.sh
./scripts/v218-release-tcp-smoke.sh
./scripts/v218-release-udp-smoke.sh
./scripts/v218-release-lifecycle-smoke.sh
./scripts/v218-jwt-verify-compat.sh
./scripts/v218-api-shape-compare.sh
```

The release smoke scripts download the official release binary for the local Linux architecture,
verify its checksum, start the Rust relay in Docker, start local upstream test
services, expose them with the official v2.1.8 CLI, and verify HTTP, raw TCP,
UDP, renewal, and unregister behavior through the Rust relay.

Passing runs currently end with messages like:

```text
official v2.1.8 CLI HTTP smoke passed: https://v218smoke.localhost:18444/ -> portal-rs-v218-smoke-ok
official v2.1.8 CLI TCP smoke passed: 127.0.0.1:19181 -> tcp-echo:hello-v218-tcp
official v2.1.8 CLI UDP smoke passed: 127.0.0.1:19182/udp -> udp-echo:hello-v218-udp
official v2.1.8 CLI lifecycle smoke passed: renew endurance 45s and unregister cleanup
v2.1.8 Go-issued lease JWT verifies in Rust
v2.1.8 Go relay vs Rust relay API shape comparison passed
```

## Interpretation

The Rust relay is **not yet fully v2.1.8 compatible** because public discovery
expansion/polling behavior and multi-hop/WireGuard runtime parity are not
smoke-tested end to end. The currently verified claim is stronger than the initial HTTP-only
smoke: the official v2.1.8 CLI can establish HTTP, raw TCP, and UDP tunnels
through the Rust relay locally; Go-issued v2.1.8 lease JWTs verify in Rust; and
the direct API envelope/status shape matches the Go v2.1.8 relay for the checked
control-plane endpoints. `/sdk/hop` canonical verification, route registry code,
HopMux framing, next-hop bridge wiring, runtime bridge metrics, overlay peer
config preparation, and an experimental `tokio-wireguard` backend now exist.
Multi-hop support still remains a compatibility gap until the overlay data path
passes local relay-pair smoke tests and Go v2.1.8 mesh interop.
