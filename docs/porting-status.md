# Portal Tunnel Rust Porting Status

Last updated: 2026-05-02

## Implemented

- HTTPS HTTP/1.1 API listener with `/healthz` and `/sdk/domain`
- Relay identity and local TLS material generation
- SIWE register challenge verification and ES256K lease JWT issue/verify
- `/sdk/register/challenge`, `/sdk/register`, `/sdk/renew`, `/sdk/unregister`
- Registry janitor for expired challenges, leases, hop routes, and port cleanup
- HTTP/1.1 reverse session admission at `/sdk/connect`
- SNI TLS passthrough listener with `0x02` activation marker
- Root-host SNI fallback to the API listener
- One-level wildcard hostname lookup after exact lease lookup
- Keyless `/v1/sign` for ECDSA SHA-256 relay certificate signing
- Raw TCP lease port transport with `0x01` activation marker
- UDP QUIC DATAGRAM backhaul and per-lease UDP listener
- Admin auth cookie, admin settings persistence, approval/ban/port policies
- Trusted proxy client IP extraction from `X-Forwarded-For`/`X-Real-IP`
- Relay discovery descriptor signing, `/discovery` endpoints, public registry bootstrap merge, bootstrap polling, self-announce, and runtime bridge `active_connections`/`tcp_bps` metrics
- WireGuard identity material generation/persistence for discovery descriptors
- WireGuard overlay peer config preparation: overlay IPv4 derivation, endpoint rendering/resolution, endpoint fallback cache, and IPC config change detection
- Experimental `tokio-wireguard` overlay runtime backend: in-process WireGuard interface creation, overlay HopMux listener wiring, outbound HopMux connector, discovery peer sync, and `supports_overlay=true` advertisement when the runtime is enabled
- `/sdk/hop` first-pass signed route verification using v2.1.8 canonical bytes, including `first_seen_at_unix_nano`, plus route registry POST/DELETE internals
- HopMux token framing/yamux runtime with boxed async I/O and ingress/next-hop bridge wiring
- Optional frontend static serving from `FRONTEND_DIST`, `/tunnel/status`, and relay install endpoints
- Dockerfile, docker-compose, deployment notes, and Dockerized smoke/CI scripts

## Known Gaps

Resolution plan: `docs/known-gaps-resolution-plan.md`

- Official v2.1.8 CLI local smoke coverage now includes default HTTP, raw TCP, UDP, renew endurance, unregister cleanup, and selected API shape comparisons. See `docs/v2.1.8-compatibility.md`.
- SIWE/JWT behavior needs fixture tests generated by the Go implementation.
- Discovery polling and public registry bootstrap merge are implemented locally, but public multi-relay discovery expansion is not yet smoke-tested against the official v2.1.8 relay.
- `/sdk/hop` verification/registry, HopMux, and overlay runtime wiring exist, but multi-hop is still not end-to-end verified with Go v2.1.8 relays or clients.
- The `tokio-wireguard` data path needs production hardening: local two-interface smoke, peer churn, NAT keepalive, MTU behavior, and Go relay mesh interop remain open.
- Managed ACME DNS providers, thumbnail generation, and embedded frontend artifact packaging are not implemented.
